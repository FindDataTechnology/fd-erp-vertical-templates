# 仓配分销线 · 边界与资金口径出街稿（单一出处）

> 用途：官网板块、方案文档、售前问答共用一套话术，避免三个出口三种说法。
> 纪律：本文件是**口径正源**，任何对外材料改口径先改这里。客户名一律不出现（客户中性）。

## 一、四句话边界（任何材料都可直引）

1. **账在我们这里，执行在外部系统。** 平台做的是记账、核对、留痕与拍板；入库出库在客户的 WMS，结算付款在客户的财务系统，干线运输在承运商的系统。我们不替代它们，只把它们串成可对账的一条链。
2. **平台不经手资金。** 没有资金池、不代收、不代付、不分账。应付/应收是台账上的数，付款是客户在自己的财务/银企通道里做的动作，平台只产出核对指令与差异清单。
3. **线上支付只读。** 微信支付/支付宝（以及后续渠道）只做商户侧的只读查询与回调记录：看得到钱到了没有，动不了钱。
4. **能力如实标注。** 尚未提供的能力，接口与页面上直接写明「该能力当前未提供」，不摆假表单、不摆假确认按钮。

## 二、口径三形态

**一句话（对外介绍/官网 banner）**
> 账在平台、执行在外部系统、资金不经手——一条能把采购到结算对平的链。

**一段（官网板块/方案摘要）**
> 我们不做又一个 ERP，而是把已经存在的系统串起来：主数据、采购、履约与计费在平台内成账，入库在 WMS、运输在承运商、付款在财务系统，各自留在自己擅长的位置。平台负责让它们对得上——每一个金额都能追到规则、事件、凭证与那次冲正；每一笔付款都只是客户在自己通道里的动作，平台只给核对结论。

**长版（方案文档 §边界）**
> 边界设计遵循三条硬约束：
> ① **零旁路**：外部系统的写入全部经连接器层，可审计、可回放；平台内部不存在绕开账本的写路径。
> ② **零资金池**：平台不设收款账户、不做二次清算、不做分账。供应商结算页是只读查询；对账差异以指令形式交给客户执行。
> ③ **零凭证外泄**：第三方系统凭证（商户密钥、证书、API 密钥）存放在连接器库内，不进业务代码、不进日志、不进移动端；移动端只持平台会话凭证。

## 三、常见追问与标准答法

| 追问 | 答法 |
| --- | --- |
| 能在平台里付款吗？ | 不能，也不打算做。付款动作留在客户自己的财务通道（银企直连/网银），平台产出的是核对指令与差异清单。 |
| 你们是不是二清？ | 不是。平台不碰资金流，只处理信息流与单据流；收付双方仍是客户与其上下游。 |
| 供应商/承运商登进来看到什么？ | 只看到与自己相关的那部分：订单、发货、对账、运单。身份未绑定时页面直接不发请求，不做任何推测。 |
| 支付渠道接了吗？ | 微信支付/支付宝的商户侧只读查询与回调已就绪（写入面为零）；真实商户凭证的联调在拿到商户资质后执行，未跑通前不计入已支持。 |
| 哪些能力还没有？ | 开票直连、售后工单、供应商对账明细、承运商运费单等 15 个端点当前如实返回「未提供」，页面对应区块明示，不占位成假功能。 |
